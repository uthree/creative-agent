# 正常と複合問題を含む音声診断スモークの実測結果

実施日 2026年11月1日 JST。

音切れ、クリッピング、左右レベルの偏りを対象に、正常・単一問題・複合問題の教師生成、多ラベルloss、encoderと診断headの実更新、保存・別プロセスでの再開まで動作した。学習処理のスモークは合格とする。現在の重みは区間検出と誤警報の品質が未達であり、実用の検出器とは扱わない。

実装はcommit `2988c61492e8a86d5127be598c417216040ff68a`。学習はcommit前に行い、実行時の全ソースと依存lockのSHA-256が、このcommitの内容と一致することを確認した。保存済み重みからの予測・loss・集計の再計算も一致した。

## データと学習

| 項目 | 条件 |
| --- | --- |
| 原音 | 自作16作品、native 48 kHzステレオ、約1.5〜2秒 |
| 派生 | 1原音から正常2、単一3、複合4の計9ケース |
| 学習 | 12原音、正常24・単一36・複合48の108ケース |
| 検証 | 4原音、正常8・単一12・複合16の36ケース |
| 複合 | 別区間の問題、同時刻の別chの問題、3種類の複合 |
| 正常 | 原音とfade付きの意図的な休符 |
| 入力 | 加工後の波形と有効位置mask。原音・操作・正解eventは入力しない |
| モデル | CNNと幅128・2層の全体双方向Transformer、左右×3種類の線形head |
| loss | clipの多ラベルBCEと、有効位置の多ラベルBCEの和 |
| 更新対象 | CNN・Transformer・norm・診断headの437,926パラメーター |
| 閾値 | sigmoid 0.5、eventの時間IoU 0.5。検証結果に合わせて変更しない |

同じ原音の派生はsplitを共有する。36件の検証入力は4つの独立原音に由来する。加工後にも信号上で各効果が残ることを検査し、無音への操作や、後段で効果が消えた例は教師として拒否した。全体RMSを原音へ揃え、そのgainを記録した。

## 更新と再開

| 実行 | 初期encoder | 最初の実更新 | 別プロセスからの再開 | AMP skip |
| --- | --- | --- | --- | --- |
| RTX 3070 | 前回SSLのstep 21 | 20回 | step 20を復元し21更新目を完了 | 0 |
| CPU専用wheel | 前回SSLのstep 11 | 10回 | step 10を復元し11更新目を完了 | 0 |

各更新の有限で非ゼロの勾配と、4つの更新対象群の重み変化を確認した。元のSSL復元headとmask tokenは未使用・凍結で、読み込み元と厳密に一致した。元のSSL重みは上書きしていない。

CUDA再開セッションは約1.44秒、PyTorch peak allocatedは29.93 MiB、peak reservedは56 MiBだった。model初期化、1更新、検証とログを含み、累計21更新の総時間ではない。依存導入、CLI起動、checkpointとデータの読み込みは計時に含めない。メモリ値はGPU全体の使用量ではない。

## 検出品質

| 指標 | CUDA 21更新後 | CPU 11更新後 |
| --- | --- | --- |
| clipの種類macro F1 | 0.20513 | 0 |
| 時刻とchを含むevent macro F1 | 0 | 0 |
| 正常への誤警報 | 8/8件 | 0/8件 |
| 単一問題の種類集合が一致 | 4/12件 | 0/12件 |
| 複合問題の種類集合が一致 | 0/16件 | 0/16件 |

CUDAでは正常へも問題を出し、区間検出には成功していない。CPUでは全検証入力を問題なしとして扱い、陽性をすべて見落とした。正常への誤警報0だけを根拠にCPUモデルを採用しない。初期encoderと更新回数が異なるため、両者をハードウェアによる品質差とは解釈しない。

単純基準では「常に問題なし」が種類macro F1 0・正常誤警報0、「常に全種類あり」が種類macro F1 0.61538・正常誤警報100%だった。どちらもevent macro F1は0。lossはCUDAで約1.24405から1.06214へ下がったが、検出品質の達成を示す結果にはなっていない。

誤event数の時間あたり指標も集計しているが、正常音声は合計約13.85秒であり、1時間を実測した結果ではない。正式な品質検証では独立した正常音・実録音と長い検証時間が必要になる。

## 検証と保存

- GPU環境で全44テスト成功。CPU専用環境で38テスト成功、CUDA専用6件skip。既存SSL・captionの回帰も含む。
- 正常・複合の教師、重なった多ラベル、同種の複数区間、ch、末尾とpadding、重複eventの一対一採点を検査した。
- CPUでは中断なしの4更新と、2更新後に中断・再開した4更新の重み・AdamW・提示履歴・最終集計が厳密に一致した。
- AMP overflowを故意に起こし、skipを実更新として数えず、重みが破損しないことを確認した。
- 全実更新とoptimizerのstep数を照合した。TensorBoardはファイルの読み出し順に依存せず、実stepの重複・欠落がないことを検査した。
- 正常・単一・複合の代表音声と正解・予測eventの3組を照合し、48 kHz・2chと、保存された入力・出力への一致を確認した。
- Ruff lint・format、依存lock検査、GitHub Actionsの[LinuxとWindowsのCPU検証](https://github.com/uthree/creative-agent/actions/runs/41280815061)が成功した。

音声、完全なmanifest、正解event、全予測、重み、TensorBoardイベントはローカルの `runs/` にのみ保存する。公開用の[集計JSON](../experiments/results/audio-diagnosis-smoke-20261101.json)には、条件、件数、指標、hash、監査結果を残した。[手順書](audio-diagnosis-smoke.ja.md)から再実行できる。
