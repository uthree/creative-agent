# 発話・音楽・環境音に共通するSSLの調査と次の実験

調査日: 2026年11月2日 JST。実装の照合先: `b95eea0`。状態: 文献調査と実験設計。ここに示す新しい損失は未実装・未学習で、既存checkpointと実行時の既定値は変更していない。

その後の進捗: [③→②の比較経路](audio-ssl-objective-comparison.ja.md)を実装した。以下は調査時点の提案を記録したもので、既存のクラスタCEの既定経路とは別の実験として扱う。

## 結論

**マスク予測は音声専用ではない。何を教師にし、何を変化してもよい情報として扱うかが重要である。** WavLMの発話教師と主話者のdenoisingを、そのまま「あらゆる音を残す」学習の目的にはしない。音楽、発話、環境音を共通のencoderで扱う最初の候補は、**直接波形パッチのEMA潜在表現予測＋音響情報の復元補助損失**とする。

設計の参照先として、汎用音声のM2D、生波形のWavJEPA、混合音のSSLAMが特に有用である。既存モデルの知識を使って早く下流性能を得る経路には、USAD 2.0型の複数教師蒸留を別に用意する。これは既存研究を組み合わせる本リポジトリ向けの提案であり、いずれかの論文の完全な再現ではない。

「あらゆる音声」は、まず可聴帯域の発話、歌声、音楽、生活音、機械音、動物音、それらの重なりを対象とする目標である。全分布での性能を保証する名称にはしない。48 kHz入力は24 kHz超の超音波を含まず、録音に存在しない帯域・左右差は学習でも回復できない。

## 一次資料の比較

以下の「適用判断」は本プロジェクトでの判断。各論文のベンチマーク値はモデル規模・入力・データ量が異なるため順位表にはしない。スペクトログラム入力の成果を、約1Mパラメータの直接波形パッチモデルの実証として扱わない。

| 方式と一次資料 | 教師・目的と研究上の確認範囲 | 適用判断 |
| --- | --- | --- |
| [WavLM](https://arxiv.org/html/2110.13900v3)、§4.2 | clean発話のクラスタを、マスクした雑音・重畳発話から予測。主発話の教師を維持する。発話タスクで評価 | 発話denoisingの対照。混在する全音源の保持とは目的が異なる |
| [MERT](https://arxiv.org/html/2306.00107v4)、§3・付録A.1 | EnCodec RVQの離散音響教師とCQTのマスク位置復元を併用し、音楽で評価。mixupの効果は教師によって異なる | 音楽にもマスク予測を使える直接の根拠。CQTだけを汎用教師にはしない |
| [BEST-RQ](https://arxiv.org/abs/2202.01855)／[MusicFM](https://arxiv.org/html/2311.03318v1)、§2.3 | 固定ランダム投影・codebookから離散教師を作る。MusicFMはlog-mel入力で音楽へ適用 | 大型教師もk-means再fitも不要な軽量対照。入力標準化とcodebook利用率の確認が必要 |
| [BEATs](https://proceedings.mlr.press/v202/chen23ag.html) | 離散音響tokenizerとマスク予測を反復し、一般音の分類で評価 | 意味情報の参照教師。分類で不要な細部を捨てる目的が、採譜・微小な欠損検出にも適切とは限らない |
| [data2vec](https://arxiv.org/html/2202.03555v2)、§3 | 全入力を見るEMA教師の文脈付き表現を、マスク入力から回帰。発話・画像・言語を個別に学習して検証 | 現在のencoderへ導入しやすい。複数音声ドメインの同時学習を原論文が実証した、と解釈しない |
| [M2D／M2D-X](https://arxiv.org/html/2404.06095v1)、§III・IV | 生徒は可視パッチ、EMA教師は隠した側だけを符号化して潜在予測。汎用音、発話への適応、呼吸音でも検証 | 汎用設計の有力な参照先。ただし原方式はスペクトログラムで、発話ではパッチ形状・時間解像度の変更も重要 |
| [Audio-MAE](https://arxiv.org/abs/2207.06405) | 可視スペクトログラムパッチから隠したスペクトログラムを復元。音・発話の分類で評価 | 外部教師不要の音響復元対照。復元誤差だけでは意味理解を判定できない |
| [EAT](https://ijcai.org/proceedings/2024/421) | EMA教師を使う局所表現予測と全体表現予測を併用 | 局所と全体を併用する根拠。原方式のCNN decoderと高mask率をそのまま採用する必要はない |
| [BYOL-A](https://arxiv.org/abs/2204.07402) | 同一音の拡張view間の表現を一致させ、一般音タスクで評価 | 負例不要の対照。音高・音色変化への不変性を、採譜用特徴へ一律に要求しない |
| [Audio-JEPA](https://arxiv.org/abs/2507.02915)／[WavJEPA](https://arxiv.org/html/2509.23238v1)、§3 | 潜在表現の予測。前者はスペクトログラム、後者はCNNによる波形前段を使用。発話・音楽・環境音を評価 | 波形入力でも有望。ただしWavJEPAはCNNなしの実証ではなく、発話や細かな音高など全課題で一律に勝つわけでもない |
| [SSLAM](https://arxiv.org/html/2506.12222v1)、§3 | 混合音の潜在予測にsource retentionを加え、重なる音源の情報を学習 | 「追加した音を消す」以外の混合学習の参照先。まず混合全体を教師とする簡単な対照から試す |
| [USAD 2.0](https://arxiv.org/html/2606.06444v1)、§2・3 | WavLM・ATST・MuQの知識を、入力ドメインに応じて重み付けして蒸留。追加段階の2.0+は教師ありモデルも使用 | 複数領域を1 encoderへ集約する実用案。ラベルなしの蒸留でも教師の学習歴・費用があり、純粋なゼロからのSSLとは分ける |

動物音にも対象を広げる根拠として、[AVES](https://arxiv.org/abs/2210.14493)はラベルなし音源による事前学習を動物の鳴き声の分類・検出へ適用している。ただし、どの方式でも発話・音楽だけの学習から機械故障や動物音への汎化を仮定せず、その領域の録音と評価を追加する。

## 現行実装で既に確認できていること

[実験報告](audio-patch20-report.ja.md)の直接パッチモデルは、音楽・英語・日本語で既に学習している。各1,000更新・3 seedの比較で、音楽の通常音声CEは`early_concat`の2.736から`patch20`の2.520へ低下した。音楽のtrain頻度priorは3.501だった。現時点の結果から「WavLMライクなので音楽では学べない」とは言えない。

ただし、現在の教師はWavLMの学習済み発話表現ではない。次の簡易的な音響教師である。

- 50 msの非重複FFT、左右powerの和、窓ごとの総power正規化、40-bin log-mel、trainだけでfitした64クラスタ。
- mask位置の離散CEのみ。denoisingは「混合入力から元音源のcleanクラスタを予測する」ことで、独立した波形復元損失ではない。
- 4秒crop、40%のmask、基本spanは4 token＝200 ms。比較用の隣接guardも適用する。
- batch内比率は音楽1/2、英語1/4、日本語1/4。半数の例に同じ群の別録音を0〜10 dB SNRで混合する。

コードの根拠は[`representation.py`](../src/creative_agent/representation.py)、[`representation_training.py`](../src/creative_agent/representation_training.py)、[`representation_data.py`](../src/creative_agent/representation_data.py)。入力decoderの[`public_data.py`](../src/creative_agent/public_data.py)には録音ごとのpeak正規化もある。

ここから先の懸念は実装に基づく仮説であり、原因が確定したわけではない。

| 現状 | 調べるべき不足 |
| --- | --- |
| 64種類のlog-melクラスタ | 同時に鳴る複数音高、細かな倍音・立ち上がりを同じラベルへ潰す可能性 |
| 50 ms FFT、40 mel bins | FFTのbin間隔は20 Hz。低域の半音差や微細な周波数変化の教師として十分か |
| 窓ごとのpower正規化 | 短時間エネルギーの変化を教師が失う。録音ごとのpeak正規化で原録音の絶対レベルも比較できない |
| 左右powerを足す教師 | 入力はステレオだが、教師は左右差・位相差の保持を要求しない |
| 音楽同士も混ぜて元音源のみを教師とする | 全楽器・全イベントを拾う学習と、特定音源を選び出す学習の目的が競合し得る |
| 合成音楽中心、JSUTは同一話者 | 未知の録音環境・生楽器・日本語話者への汎化の根拠が足りない |

生波形を入力しても、圧縮後の表現が位相などを保存する保証にはならない。20 FPSは特徴の時間刻みであり、可聴周波数の上限を10 Hzにする意味でもない。一方、50 ms内の微小イベントや音符の境界を読み出せるかは独立した評価が必要になる。

## 推奨する最初の設計

### 共通encoderと潜在予測

`48 kHz stereo → 非重複50 ms patch → Linear(4800, d_model) → 双方向Transformer → 20 FPS特徴列`を維持する。最初は現在と同じ`d_model=128`・2層とし、損失変更と大規模化を同時に行わない。幅を増やすときはパッチ投影の出力も同じ幅にする。CNNや時間方向の平均プーリングは追加しない。

最初の実装は既存の全長mask-token経路を利用する、**data2vecを参考にしたEMA潜在予測**とする。

1. 元の観測波形をマスクなしでEMA教師に渡す。「clean」は人工的な追加加工前という意味で、自然な背景音も教師の一部である。
2. 同じ波形のパッチを隠した生徒が、対象時刻の教師表現を学習用predictorから予測する。
3. 教師側だけで有効位置を使って正規化し、stop-gradientを適用する。最初は最終層の表現を対象とする。教師の上位層の統合は独立した比較とし、時間方向の間引きは行わない。
4. 生徒・predictorはmasked latentのSmooth L1で更新し、教師はFP32のEMAで更新する。教師はoptimizerへ入れない。
5. EMA係数、正規化、warmup、教師・生徒の分散を記録する。EMAとstop-gradientだけでcollapseしないとは仮定しない。

これは可視位置だけをencoderへ送るJEPAや、教師が隠した側だけを見るM2Dの忠実な再現ではない。まず教師の種類を変える実験を成立させ、その後に**全入力教師とM2D型の隠れ側教師**を比較する。可視tokenだけの計算への最適化も、品質と計算量を分けて確認してから行う。疎な列でも原音の秒座標を維持する。

### 音響情報を残す補助損失

潜在予測だけでは、採譜・音の欠損・左右差まで十分に残るとは限らない。全ドメインに適用できる候補として、同じ観測波形から計算する多解像度log振幅スペクトル、短時間logエネルギー、左右のレベル差をマスク位置で予測する。教師を作るDSPは学習時だけ必要で、推論encoderへSTFTやCNNを追加することにはならない。

最初のスペクトル窓候補は20／50／200 ms、hopは10 ms。1つの50 ms tokenから順序付きの複数subframeを出力するheadを使い、教師を50 msごとに平均しない。FFT等の窓の支持域を明示し、完全に隠された原音範囲に収まる教師subframeだけを採点する。長い窓について有効な教師がなければ、そのheadのlossを掛けない。単にラベルを20 FPSへ平均して合わせる実装にはしない。

短時間エネルギーは窓ごとに総powerを1へ正規化しない教師から作る。最初の損失比較では既存の入力前処理を全条件で共有し、そこで測れる録音内の相対変化を対象とする。原録音レベルを保持する前処理の比較は次段階に分ける。未校正の録音から音圧レベルを学習したとは扱わない。mono複製には左右差のlossを掛けない。

振幅スペクトルと左右レベル差だけでは位相・空間情報の保持も保証できない。位相反転や左右の遅延に対するprobeで不足を測り、必要なら複素スペクトルや相互相関の教師を別に比較する。全headを最初から増やして有効性を判断しにくくしない。

音楽のpitch probeが弱ければ、MERTを参考にフル音域のCQT復元を追加比較する。これは最初の汎用lossの必須項目にはしない。CQTの低域は50 msより長い支持域を必要とするので、上記と同じ支持域の検証と長いmaskが必要になる。12次元chromaだけではオクターブ情報を失い、MIDI用教師として不十分である。

```text
L = L_masked_latent
  + λspec × L_masked_multires_log_spectrum
  + λenergy × L_masked_log_energy
  + λstereo × L_masked_left_right_level_difference
```

各項は有効な例・mask位置・subframe・特徴数で正規化する。ドメインごとに平均してから重み付けし、長い音楽や特徴数の多いheadだけが支配しないようにする。係数は固定したtrain校正batchでlossと共有層への勾配規模を確認して事前に決め、値・校正手順をplanに保存する。正解MIDI・文字起こし・イベントラベルはSSL教師に使わず、probeと下流評価に使用する。

### 混合音と加工音の扱い

| 学習の目的 | 教師に含める音 | 最初の扱い |
| --- | --- | --- |
| 音場全体を理解する | 発話、伴奏、環境音など観測された全成分 | マスクだけを施す。元録音の背景音を自動的に除去対象にしない |
| 人工的に2音源を混合して理解する | 人工混合後の両方の成分 | 教師も混合後の波形から計算する対照を作る。次にSSLAM型source retentionを検討 |
| 指定された主発話を雑音から取り出す | 主発話だけ | WavLM型のdenoisingを別設定で比較。汎用SSLの唯一の目的にしない |
| clipping・dropout等を検出する | 加工後の観測された状態 | 加工後の音響特徴を残す。正常音への復元だけを要求しない |

MERTでもmixupは使われているため、混合自体が音楽に不適切とは結論しない。違う音を足すか、それを教師から除くか、除く対象を音から識別できるかを分ける。実音の楽器群と人工的な妨害音を同一視しない。

pitch shift・time stretch・チャンネル交換・音量変更への完全な不変性は、共通特徴へ一律に要求しない。音高、テンポ、左右、レベル差が正解を変える課題を含むためである。必要なら意味用の学習head内でのみ頑健性を学び、主経路の時系列特徴を保持する。全体の分類headを追加するときも、局所系列を置き換えず、学習可能な集約を比較する。

## 比較の順序と評価

### 1. 同じ入力で損失を比較する

まず以下の3条件を、同一encoder・データsplit・入力順・mask・更新数・seedで比較する。新規比較では全条件とも人工混合なしとし、教師の違いを切り分ける。過去の混合ありの実測値を、新条件の対照値として流用しない。

| 条件 | SSL損失 | 役割 |
| --- | --- | --- |
| A | 現在のtrain-fit 64クラスタCE | 再学習する基準 |
| B | EMA潜在予測 | 特定の離散教師への依存を外す |
| C | B＋多解像度スペクトル・エネルギー・適格な左右差の復元 | 細部を保つ補助lossの効果を見る |

CPU／GPUの短い配線検証後、各1,000更新・3 seedでスクリーニングする。選択はvalidation probeで行い、loss値の絶対比較では選ばない。異なる損失のCEと回帰値は同じ尺度ではない。採用候補とAを各5,000更新・3 seedへ進め、固定testを最後に一度評価する。これは提案する次回条件であり、今回実行した学習ではない。

データは発話／音楽／環境音を各1/3の例数で開始し、発話内の日本語／英語は均衡させる。小さいcorpusの過剰反復も記録する。環境音未取得の段階なら発話／音楽だけの結果と明記し、汎用音の検証完了としない。全条件で追加データを共有し、データ追加とlossの変更を混同しない。

### 2. 汎化を測る

凍結encoderの共通probeを主評価とする。[HEAR](https://proceedings.mlr.press/v176/turian22a.html)のように複数領域を測り、平均だけで弱い領域を隠さない。大規模なHEAR全課題の実行を、最初のスモーク条件にはしない。

| 領域 | 優先するprobe／下流評価 | 分割と注意 |
| --- | --- | --- |
| 発話 | 音素・短い発話内容のprobe、後段のLLM ASRでCER／WER | 話者・録音元を分離。probeの記号ラベルは評価用で、CTCを製品のASR経路へ戻す意味ではない |
| 音楽 | 多音高、octave誤り、onset／offset、楽器、後段のMIDI note F1 | 同じ曲のstemをsplit間に分けない。未知音色・実録音を追加する |
| 環境音 | clipの多ラベル分類と、同時イベントの検出・時間境界 | 元録音・場所・録音条件を分離。小さなESC-50等は公式foldと評価汚染のない手順を使う |
| 音の品質・局所性 | 正常／複合問題のF1、正常時誤警報、短い欠損、左右差、境界誤差 | 意図的な無音や歪みも含む。ラベルは診断probeに限定する |
| 入力依存・collapse | 無音・別音源・左右交換・音高変更による特徴と予測の変化、特徴分散・有効rank | 教師・生徒を別々に監視し、loss低下だけを成功としない |

probeはランダム初期化encoderとも比較し、head構成・学習予算を揃える。splitはwindow作成前に固定し、すべての教師fit・標準化・係数校正はtrainのみで行う。既知の基準として凍結したBEATs等を追加する場合は、入力帯域・チャンネルと教師の事前学習データの重複を明示する。

短期比較は現在の4秒cropを使って損失差を見る。その後、音楽の30秒・60秒、発話・環境音の複数長でも学習・評価する。30秒・60秒の推論が動くだけでは、長い文脈の学習成功とは数えない。現行`crop_seconds`の上限10秒、batch設計、mask、保存・再開を拡張する必要がある。時間精度が弱ければ、損失の比較後に同じ直接パッチ方針の20 ms＝50 FPSも独立比較する。

信頼区間や再標本化は独立した元録音・曲・話者を単位とし、同じ曲のstemや反復cropを独立例として数えない。教師lossの改善をASR・採譜性能の改善とは呼ばない。

### 3. 良い目的が定まってから拡張する

1. 全入力EMA教師とM2D型の隠れ側教師を比較する。
2. 混合全体を教師にする学習と、主音源だけのdenoisingを別条件で比較する。全音源の検出が弱ければSSLAM型の保持目的を検討する。
3. 音楽のpitchが弱ければCQT／RVQ教師、発話内容が弱ければ発話教師を追加する。新しいheadの有効例数・勾配を個別に記録する。
4. 自前SSLからの性能不足と学習予算を確認して、USAD型の専門教師蒸留を別系列で試す。WavLM／一般音／音楽教師の時刻対応と異なる幅は、順序付きsubframe予測・学習可能な射影で合わせ、時間平均で潰さない。
5. 最後に幅256／384や層数、長文脈化を比較する。20 FPSの出力をLLMへ直接投影し、接続時にさらに5フレーム間引かない。

## 実装時の検証・ログ・保存

追加実装では、教師の無勾配・EMAの実更新・padding除外・checkpointからの教師とoptimizerの厳密再開を検証する。隠した原音だけを摂動して生徒の可視埋め込みが変化しないこと、長い教師窓の支持域と採点maskが一致することも確認する。全区間の統計を使う入力正規化も点検対象とし、教師の計算経路から生徒へ正解を渡さない。

TensorBoardには領域別の各loss・勾配・分散と、固定入力の音声、mask区間、復元スペクトルと教師、エネルギー・左右差、probeの正解と予測を記録する。SSL単独にLLM応答やMIDIが存在するとは扱わず、後段を学習した段階で応答・楽譜比較を再接続する。

調査時点で永続ディスクの空きは約78 MiBであり、新たな複数runのcheckpoint保存には不足する。実行前に利用可能な永続保存先と必要量を確認する。既存成果物は削除せず、RAM上の一時領域だけを唯一の重み保存先にもしない。大型教師や特徴cacheの取得は今回行っていない。
